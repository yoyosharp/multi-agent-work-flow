# Core spec — the minimal binding spec (v6.6.1)

What remains when every DIRECTION line and every DROP line is removed, every buried rule is promoted into the checklist that executes it, every duplication is collapsed to one normative home, and every stale or contradicted line is corrected. One line per rule; the normative home cited per item states it in full — join-point copies cite it by ID and never restate its content.

## C.1 Core stratum — the task workflow

1. **Phase sequence.** plan → plan-review → human approval → impl → §3.1 pre-test review → fix → unit-test → test-result-review → manual-test → test-result-review → final review → DONE → delivery approval → DELIVERED. Home: `control-plane-pm.md` §2. The 14-phase enumeration as data lives in `board.sh` `PHASE_KEYS` (intake, charter, plan, plan-approval, impl, pre-test-review, adjudication, fix, unit-test, manual-test, final-review, done, delivery-approval, delivered).
2. **Status machine.** `PLANNED → IN_PROGRESS → IN_REVIEW → DONE → DELIVERED`, plus `BLOCKED` (infra/API outage, resume after human action). Status is read from the TASK_LIST `### <date>-<slug> — <STATUS>` heading and from nowhere else (board.sh `collect_tasks()`); the heading's machine-read contract is declared in `TASK_LIST.template.md`.
3. **Charter contract.** A brief is binding when it carries: goal, acceptance scope with explicit exclusions, ≥3 falsifiable acceptance criteria each paired with an evidence command, data-class line, risk line, manual-test direction, base/agent branch, worktree, phase, constraints, gates, definition of done, and `Binding: anchors B1–B6`. A brief missing the risk line or with <3 falsifiable criteria is unready; the task stays PLANNED and the gap is named in qa.md. The charter may add tighter gates or extra evidence, never relax or restate an anchor; it never carries file:line edit instructions or a pre-decided implementation. (brief.template.md; control-plane-instructions.md §3.)
4. **Anchors B1–B6.** B1 gate-output tail in the CLOSE entry; B2 every SHA/path/excerpt next to its claim with a confidence label `(observed)/(derived)/(inferred)`; B3 handoff block (≥4/6 signals); B4 boundary surprises go to the plane via inbox, never self-fixed; B5 every DEBUG session gets a `Root cause:` line; B6 unknowns go to qa.md. Authority: Anchors > Toolkit > Project facts > Charter. (anchors.md; worker-close.md; verify-duties.md.)
5. **CLOSE criteria.** A phase CLOSE requires: a CLOSE entry carrying the B1–B5 evidence; every evidence token verified (`closecheck.sh ratify`); each inferred claim named confirmed or rejected next to the `claims checked: <N>, wrong: <M>` counter line (an unconfirmed inferred claim blocks the IN_REVIEW flip); the entry hash-chained (`chain.sh append` after the successor handoff is written, never before). ANCHOR-FAIL closes nothing. Pre-v6 worklogs with no chain lines are grandfathered until the first v6 CLOSE on that worklog starts a chain.
6. **DONE requires** a `manual-testing.md` verdict PASS/FAIL or a human-signed WAIVE. The plane never waives. No verdict → no DONE. (control-plane-pm.md §2 Statuses; verify-duties.md Manual-test campaigns.)
7. **Delivery rule.** DELIVERED = the plane-prepared cherry-pick of non-`TEST_` commits individually, never `git merge --ff-only`, after the §3.3 pre-flight, with the human approving in a single decision. Pre-flight: (a) `manual-testing.md` verdict or WAIVE; (b) every plan-doc item deferred to manual-test individually waived or covered — a blanket WAIVE does not clear scheduled items. Executed from `docs/workflow/delivery.md`; `delivery.sh` is the mechanical half (its verdict check is a weak presence heuristic).
8. **Release state machine.** Human input is HELD when filled (ANSWERED / ADJUDICATED — editable, no side-effects) and RELEASED at the human's next REPL interaction (any natural confirm releases; verbal fill = fill+release in one step; no `release` command exists). A board Submit is fill+release in one step, only on an explicit Submit press. CONSUMED when the worker reads and acks it. Polls never auto-release. Review findings are actionable only from a completed pass (`Pass complete — F<first>..F<last> — <timestamp>`); plan decisions follow the same release semantics (→ APPROVED / DROPPED, or REVISE back to OPEN). (qa/review/plan templates; async-inputs.md §2; control-plane-pm.md §2.)
9. **Token lifecycle.** DECLARE → plane ratifies (atomic grant of execution + all resource tokens together, or DENIED with reason) → EXECUTING (flipped on first write) → RELEASED / STALE / CHALLENGED / REVOKED. Concurrency iff write domains disjoint AND resource tokens disjoint. STALE is informational, never destructive; the challenge ladder fires only on an admissible claimant; kill failure = NO successor grant, escalate, domain stays locked. Heartbeat is artifact signals only — a live pid is bonus, never authority; `host:pid` is informational. (parallel-agents.md §3–§5; workers.template.md.)
10. **Risk gate.** High/critical claims are NOT GRANTED until the human confirms — the plane asks in qa.md (title carries "risk"), the human answers, the plane mirrors RELEASED, only then GRANTED. `closecheck.sh risk` fails a granted one with no released confirmation. The gate is in the ratify checklist (verify-duties.md) and control-plane-instructions.md §4. Scope is per claim row, not per tool/action.

## C.2 Implementation stratum — the execution units

11. **Roles and entry points.** Plane (`/control-plane`), worker (`/worker <slug> [label]`, label defaults to the task short), scoper (`/grill`, user-invoked only), helper (`/helper`, user-invoked only). The plane never edits task code; the plane spawns a terminal session only on the human's explicit order; §3.1 / plan-review / test-result-review are plane-owned *sub-agents*, not terminal sessions. Workers never dispatch plan-review, §3.1, or test-result-review — stated in `commands/worker.md` and in each review skill's Guards (the hook cannot enforce it). Exploration sub-agents may be spawned by any role for its own work; review sub-agents are plane-only. **Sub-agent retry (spawn-and-watch):** the retry responsibility belongs to the spawner — record the dispatch (time + sub-agent + expected verdict) in the task worklog; if the sub-agent dies or no verdict arrives within STALE_AFTER, re-dispatch once, then escalate (to the human, or to the plane if the spawner is a worker) if it dies again; detection is the runner's overdue check for the plane-as-spawner, the parent session for a worker-as-spawner. (control-plane-pm.md §2.)
12. **Session-declared roles (v6.3).** A session declares its role via `declare-role.sh <role> [slug]` → registry `.history/_sessions/<pid>` (atomic tmp+mv write, own pid only). The hook reads registry → env var → cwd. Unclaimed = plane. Invalid roles are discarded (fail-closed). The registry is a guardrail + audit signal, not a sandbox. `phase-done.sh` deliberately retains its env-var/cwd derivation (the Stop hook runs where the agent pid walk is unreliable — documented as intentional in its header).
13. **Fixed toolkit.** One exact allowlisted invocation per script (permissions-manifest.md C1–C7). Composed one-liners drift out of every allowlist rule and prompt each time; a repeated prompt means a missing tool — tell the plane, never re-compose. `api.sh`/`evidence.sh` are the only evidence writers; `curl | tee` appends are forbidden. Compound commands are evaluated per segment; process substitution is never pre-grantable.
14. **Poll / diff protocol.** The periodic runner is the workflow clock: `runner.sh` runs one cycle every 3 min (cron / Task Scheduler) — `tick --plane --diff` (hard-fails on an unresolvable slug) → wake the plane on a real diff (workers by role if it concerns them); overdue check (WAITING rows older than STALE_AFTER, oldest first) → wake the plane with an overdue notice; board regen conditional on the diff. The runner needs no tmux and no long-running process. Workers run `tick.sh --diff <slug>` on a durable recurring wake at HOT_RATE 3 min, laddering to WATCH 10 min after 10 empty polls (markers present) and IDLE_CAP 30 min (otherwise); any change snaps to HOT. `tick --diff` prints changed sections only; a snapshot advances only to a state already reported as changed. Declare-time slug resolution (unique short → full slug; no match/ambiguous → refuse) lives in `declare-role.sh`, following `server.sh resolve_taskdir`.
15. **Wake discipline.** A pane is never guessed (registry only); pre-check pane alive + running the agent CLI; one wake per non-empty diff / per changed inbox; a wake is a nudge — the woken session still runs `tick --diff`. Phase 2: a WAITING/BLOCKED worker's registered pane is woken on inbox change. Missed wakes are covered by the ladder poll, never by re-sending. The runner watches task artifacts + TASK_LIST + worktrees only, never board output (board-blind by construction).
16. **Resume / re-ground.** After interruption, context loss, or a long gap: reload the role file + anchors, run a full-state tick, read inbox + claim row, heartbeat before writes; resume by grant state (GRANTED/EXECUTING → resume; STALE/CHALLENGED → heartbeat, wait; DENIED/REVOKED → read-only). Read the latest successor handoff before repeating discovery; verify its pointers against the current diff.
17. **Shutdown.** Plane-only `/shutdown` → `shutdown.sh`: role check, write `SHUTDOWN.md`, one SHUTDOWN inbox row per live-claim task, direct pane nudges, blessed `server.sh stop` only, write `._watcher_stop` (the runner stop marker — the filename is kept so live systems mid-migration are not broken), remove the runner's scheduled job, clean pane registry, append the still-live list, release `plane.lock`, report. Fire-and-forget: no wait, no end-state verification; unreleased claims go to the next boot's STALE sweep; never force-release a claim. Workers obey the signal and never run `/shutdown` themselves.
18. **Constants.** HOT_RATE 3, WATCH_RATE 10, IDLE_CAP 30, BACKOFF_AFTER 10, STALE_AFTER 30, CHALLENGE_WINDOW 20, LOCK_STALE 2·IDLE_CAP = 3600, RELAY_STALE 30. Slug charset `[a-z0-9-]`. Single home: parallel-agents.md Constants; every other file cites it, never restates the values.

## C.3 I/O stratum — presentation + adapters

19. **The board (Board v2).** Overview + one detail page per live task, generated from `.history/` (status from TASK_LIST headings only). Stepper over the 14 phases; gates-only inbox (open Q/F/D, plan-approval, BLOCKED-on-human, IN_REVIEW→final-review, DONE→delivery); fleet matrix; per-task docs tabs + trace (Compact/All/Raw); delivery prerequisites checklist rendered from the Core DONE/delivery criteria. **Write rule: board forms write ONLY on an explicit Submit press; no autosave; one Submit = the whole batch; Submit = fill+release in one step; hash-guarded (409 stale / 422 invalid).** Serve mode binds `127.0.0.1` only; `/relay` emits canonical inbox rows for the four gates + WAIVE (reason required). Auto-refresh 180 s. Orphan task pages are pruned. Board regen rides the runner cycle (non-empty diff) and is conditional on the diff, never blind.
20. **Status / reports.** `status.sh` (TASK_LIST headings, claim rows, WAITING/BLOCKED-first state lines, signal freshness, worktrees — read-only, consumed by `boot.sh`'s sweep). Worker phase reports (7 fields, evidence paths not copies — reporting-instructions.md §1). Plane summaries (report-first, cross-task, concise; at IN_REVIEW include the worker's method + case-derivation trace alongside the diff summary). Token reports (`tokens.sh`: dedup by message id, fresh = input+output+cache_read+cache_write).
21. **Adapters.** The API index (`.history/_shared/api-index.md`, the only shared record; keyed by `METHOD + path`; lookup-first; source controller + sha, staleness re-checked; `discovered-by` origin kept, newest `last-verified-by` wins on merge; no secrets — auth by reference to `api-config.env` only; a refused merge blocks the IN_REVIEW flip). The GitHub push route (scrubbed snapshots via the connector's push-files; never unscrubbed, never a PAT in a git command). Future adapters (DB / management tools) plug in here, not in Core.

## C.4 Enforcement aspect — woven at its join points

22. **J-E1 Tool-call interception.** PreToolUse `domain-guard.sh` (exit 2 = block, no retry). Rule 1: no Read/Edit/Write under `~/.ssh`, `~/.aws`, `*.pem`, basename `*secret*`; no Edit/Write to `settings.json` or `hooks/*`. Rule 2: no `rm -rf`, no force-push, no curl/wget except localhost. Rule 2b: no raw kill/pkill/killall (including `kill -0`); only blessed `server.sh stop` — blessed path, verb `stop`, no extra args, worker only its own slug, live-pid verification (cmdline marker + worktree cwd + LISTEN socket; `MT_SERVER_MATCH` unconfigured = deny; pidfile never trusted). Rule 3: per-role write domains (plane `.history/` only; worker own worktree + own task dir; scoper `.history/_pending/` + `.history/_shared/` (its queue list, v6.6.1 §53/6); helper the fail-closed allowlist — plus the exact file `docs/workflow/keys.md`, which the helper alone may write). `0.scratch/` is writable by EVERY role for reports (v6.6.1 §53/4), on top of each role's domain. Rule 4: worker code writes must sit under a path token from the claim row's Write-domain cell. Registry carve-out: a session may write exactly its own `.history/_sessions/<pid>`. The hook's seven code-only rules get one prose line each in `verify-duties.md`'s Server lifecycle section (`kill -0` denial, no-extra-arg stop, blessed-path resolution, `MT_SERVER_MATCH`-unconfigured-deny) or are ruled code-only by design here (`resolve_taskdir` live-row-wins, registry carve-out, `is_agent_cmd` snapshot exclusion). Codex enforcement ships in the package (v6.6): PreToolUse `domain-guard.ps1` via `.codex/hooks.json`, JSON deny on stdout with exit 0 — the v6.5.1 "no Codex enforcement" line is superseded.
23. **J-E2 DECLARE / ratify.** Grant atomically or deny with reason in `workers.md`; method-fit check; risk gate (item 10); flip TASK_LIST PLANNED → IN_PROGRESS at the first GRANTED claim, as a step in the ratify checklist (B-1 — verify-duties.md, the ratify checklist of record; control-plane-instructions.md §4 stays stubs); the heading flip and the workers.md phase-cell update happen in the same curation beat. BLOCKED rows are answered within one poll cycle (B-5) — enforced by the runner's overdue check. Umbrella sub-task serialization: the plane tracks the last-committed enum tail and N+1 rebases onto N's tip (B-6 — control-plane-instructions.md §3).
24. **J-E3 CLOSE.** `closecheck.sh anchors` → `closecheck.sh ratify` → IN_REVIEW flip at the first review CLOSE (verified impl CLOSE, when §3.1 starts); the task stays IN_REVIEW through the final review → claims-checked counter + inferred-claim naming in the worklog. ANCHOR-FAIL closes nothing. FIFO: on CLOSE verify, the oldest WAITING row is verified first.
25. **J-E4 Human gates.** Plan approval (plan.md gate file; mutual agreement = plane `plan-review … VERDICT: CLEAN (rev N)` + the worker's rev-cited acceptance line after it; 3-pass negotiation limit, then the disagreement surfaces to the user; a contested finding goes to the plane, which upholds or drops it — never back to the reviewer; impl starts when every decision is APPROVED or DROPPED; REVISE sends just that decision back). Findings adjudication (FIX/DROP/DEFER A-slots; DROP-direction releases mirror straight to DROPPED; fix only adjudicated findings from a completed pass; both test workers start only after adjudicated findings RESOLVED/DROPPED). Final review (IN_REVIEW handoff: diff summary + method/case trace; user review is final). Delivery approval (item 7 — executed from `delivery.md`). Board Submit is the sole exception to "agent markers never authorize human-gated work" — its authority covers QA/review/plan A-slots only, not delivery approval.
26. **J-E5 Server lifecycle / kill-gate.** Boot only via `server.sh start` (refuses without `MT_BOOT_CMD`/`MT_SERVER_MATCH`/discoverable port; rejects shell metacharacters in BOOT_CMD); stop only via blessed `server.sh stop` (TERM → grace → KILL → verify dead or escalate; UNVERIFIED refused, never raw-killed; STOPPED is an idempotent no-op); live server at CLOSE blocks the IN_REVIEW flip; if the worker is gone the plane runs `server.sh stop` itself. Windows drops the worktree-cwd check (disclosed) and the windows lock has no cwd binding (disclosed — no reliable pure-PowerShell mechanism without P/Invoke PEB reading). Mac lock parity via `lsof -p <pid>`.
27. **J-E6 Singleton lock.** At most one live plane. `plane.lock` (`host:pid` line only — never parse the timestamp as the holder; LOCK_STALE 3600 = 2·IDLE_CAP). Take refuses a live holder and a fresh-but-unverifiable holder (escalate to human); stale takeover only. The runner's `tick --plane --diff` refreshes the lock; worker polls never touch it.
28. **J-E7 Gates on gates.** `selftest.sh` proves every mechanical gate CAN fail (and pass) — a gate that cannot be shown to fail is a broken gate; run after any gate change and before adopting an update. `eval.sh` proves a fresh install behaves identically on a second project/machine (40 scenarios, 79 checks). Windows selftest is static-only (disclosed gap — windows gates are proven by run-server-matrix + live runs). The forbid-rule selftest assertion greps `control-plane-pm.md`, `commands/worker.md`, and the three review skills. The helper allowlist has an agreement assertion (selftest parse-and-compare). The claim-row parser is a single shared parser (`claim-rows.sh`, sourced) and the CLOSE extractor is shared (`close_text`) — a ledger-format change lands in one place.

## C.5 Auditability aspect — observing, not participating

29. **J-A1 Token / time measurement.** `tokens.sh` (linux/mac) and `tokens.ps1` (windows): dedup by message id; per-session and per-day reports; fresh = input+output+cache_read+cache_write. The poll-rate ladder is the spend control (it exists because idle sessions burned ~87M tokens/night).
30. **J-A2 Metrics rows.** `metrics.md`: a number cited in a review, report, or retrospective without its row here is an opinion, not a measurement; each row names value, recompute command, scope, date last ran, known limits; recompute before citing; stale >30 days flagged, not cited. Rows are recomputed at ship time; empty seeds are filled or removed.
31. **J-A3 Workflow self-measurement.** `eval.sh` (linux/mac) and `eval.ps1` (windows): 40 scenarios on a fresh install in a temp project (init, anchors, ratify, risk, chain, runner, stop hook, templates, domain guard, line cap, metrics row, API index incl. cross-machine, server lifecycle + kill-gate, board, lock, agent-config mapping, shutdown, scoper, helper, registry, board v2). EVAL-PASS only on 0 failures.
32. **J-A4 Estimation.** No artifact. Nothing predicts a task's cost or time before it runs. The tree measures retrospectively only. A capability to build, not a misclassification — not a v6.5 build item.
33. **J-A5 Efficiency.** A reporting discipline, not a tool (reporting-instructions.md §4): state whether phase profile or efficiency evaluation; define every rate's denominator; reconcile category/session/overall totals; compare comparable tasks/windows with the same collection + attribution method; do not call a category waste without a defined baseline/criterion. No measurement tool exists.
34. **J-A6 Governance.** The audit trail (worklog, claim rows, chain, defect ledger) + the claims-checked counter (verify-duties.md: `claims checked: <N>, wrong: <M>` at each IN_REVIEW flip, feeding metrics.md). No spend bound is stated anywhere and nothing alerts on it; governance is retrospective only. No consolidated compliance view across gates — compliance is per-task, in worklogs.
35. **J-A7 Gate-compliance observation.** The claims-checked counter + chain verification give per-task compliance data. The chain is the trust anchor of the audit trail (a rewritten/forged CLOSE entry breaks its hash; `closecheck.sh anchors` fails the gate on CHAIN-FAIL).

## C.6 Bootstrap aspect — weaving the workflow into a project

36. **J-B1 Adoption.** Template location user-declared (a URL → clone; a local path → copy; the adoption takes it as an input instead of the docs prescribing copy vs clone) → verify template → copy-first to root (`.agent/`, `.history/`, `docs/`) → pre-install check first (no writes before it passes) → run init (idempotent, keeps adapted files, never overwrites `api-config.env`, receipted) → fill project values only if the project uses `api.sh` (one `api.sh login` smoke test) → adoption checklists (fill every `<…>`, FLAGGED adapted items go to the human, never rewrite adapted rules) → per-project parameters (hook allowlist localhost-only by default, replace in the installed hook; `<PROJECT_REVIEW_CHECKLIST>`) → hook live-probe (one headless out-of-domain edit must block, exit 2, file untouched; a script smoke test is not a live probe) → register the runner (cron / Task Scheduler, every 3 min, verify before declaring boot complete) → verify (selftest SELFTEST-PASS, tick `--diff` twice, status runs, no leftover `<…>`, receipt has no unhandled FLAGGED/DEGRADED, parent `git status` clean). Hooks do not exist at adoption time — adoption runs unguarded by design; the live-probe verifies the guard after wiring. The harness flag is a (harness, kernel) pair (`-Harness <claude|codex>`, never hardcoded). Init does not scaffold `.codex/` — the Codex scaffold is provided by the ADOPT Codex scaffold step / workflow-init copy (v6.6); a fresh clone running init alone still has no Codex guard.
37. **J-B2 Migration.** Template clean check (dirty `.workflow/` = adaptation in the wrong place, surface to human, do not pull over it) → note current version → `cd .workflow && git pull` → diff old vs new pin (upstream to take, adaptations to keep — adaptations live in installed root files, never in `.workflow/`) → port, never blind-copy → init repair mode → re-verify. Helper's part: diff + write the migration plan into `0.scratch/` (allowed); the product is the report; the applying agent applies via init repair. No pinned version anywhere (deliberate).
38. **J-B3 Template refresh / versioning.** The nested clone is pristine upstream; never hand-edit it; `/.workflow/` in `.gitignore`; a fresh clone has no `.workflow/` and the agent must clone first. Version labels are re-labeled on ship — no stale migration/decision text ships.
39. **J-B4 Init / floor check.** Hard floor (git present, inside a git work tree, templates present, `declare-role.sh` present from some source) aborts with no writes; soft gaps produce a degraded install with the receipt saying so (never a silent partial install; never present a degraded install as a full one). The receipt (`.history/_init_receipt.md`) is the install's own audit record.
40. **J-B5 Port provisioning.** Per-platform `_bin` mirrors; exact-path allowlisting, no wildcards; scripts under `.history/` per-component gitignored (only `_shared/api-index.md` shared); copy updates deliberately. Windows mirrors missing: api, board, boot, evidence, shutdown (mechanism-bound or unordered candidates — disclosed gap). Windows is schedule-driven by design (the runner on Task Scheduler, no watcher, no tmux wake).

## C.7 Memory aspect — the records, at every layer's write join point

41. **J-M1 Core writes evidence.** CLOSE entries (+ chain lines), brief, TASK_LIST status. Scaffolded what the machine reads: `chain: <hash>` lines in `worklog.template.md`; the TASK_LIST heading's machine-read contract; the inbox relay vocabulary (`PLAN-APPROVED` / `WAIVE` / `FINAL-REVIEW-CONFIRMED` / `DELIVERY-APPROVED` / `TASK-COMPLETE` / `CLEANUP` / `SHUTDOWN`) and an Ack shape in `inbox.template.md`; a pass-timestamp field in `review.template.md`; a `Risk` field in `intake.template.md`.
42. **J-M2 Implementation writes worklogs + claim rows.** Append-only, never rewrite above the last entry; raw traces go to `debug-notes.md`, not the worklog. State lines (`state: ACTIVE <phase>` / `state: WAITING kind:<answer|dependency|access|plan-approval> clearer:<who> since:<HH:MM>` / `state: BLOCKED kind:<decision|dependency|access|process> …`) — one per transition, the worklog's last line while active, machine-read by tick/status/stale/board. First worklog entry carries Method + Commitment (mirroring the claim row). Successor handoff on resume (goal/phase, discoveries + pointers, decisions, tests + evidence paths, commit/dirty state, unresolved questions, exact next action) + required trace (brief's manual-test direction → derived cases → why-covered) + `Skipped <step> because <reason>` lines. Method footprint is learning, not a gate.
43. **J-M3 Enforcement writes verdicts.** Ratify outcomes, adjudications (FIX/DROP/DEFER), CLOSE ANCHOR-PASS/FAIL, claims-checked counts, risk confirmations, delivery verdicts — all recorded in the worklog / qa.md / review.md status tables and the worklog closing entry.
44. **J-M4 I/O writes board pages as history.** Per-task pages + orphan pruning (`prune_task_pages()`). The board is the primary surface *and* a historical record; the two roles share the same generated pages.
45. **J-M5 Cross-cutting records.** Defect ledger (Memory primary, Auditability secondary — the governance input). API index (Memory primary, I/O secondary — the adapter to the codebase). Metrics rows (Auditability primary, Memory secondary). The receipt (`.history/_init_receipt.md` — the init record). The event log (`.history/._events.log` — phase-done signals). `.agent/` records are retained with the task's `.history/` (no separate expiry). Retention rules for these records live nowhere in the tree — an open question, not a v6.5 build item.

## What is EXCLUDED from this spec (deliberately)

- **All DROP items:** the commented worked example with real-looking credentials in `api-config.template.env`; the live project adoption records in `control-plane-pm.md` and `parallel-agents.md` (their single home is the project-local `docs/workflow/adoption-record.md`, not the template files — the 100-line cap forced the move, and the template files stay byte-exact); the "no new shared board" sentence (pre-v6.4, contradicted); the async-inputs.md compressed restatement of cp-pm.md §2; metrics.md's two empty-seed rows; `plane-watch.sh state_get()`, `shutdown.sh state_put() {:;}` stub, `init.sh hook_ok` write-only variable; workflow-init "Re-running init is safe" (restates step 2); README Install 5–6 (v4→v5 / v5–v5.1 migrations, obsolete).
- **All DIRECTION items:** rationale paragraphs, *Why* blocks, historical notes (ruling dates, cadence-retune history, burn motivation — the burn figure itself lives in metrics.md), the "do not improvise" sentence (four copies, normalised to one wording), the payload budget (`≤100KB` tool result, `≤16KB` brief — advisory, no enforcement hook), session-length guard (40–45 min), attribution notes, dependency/portability notes, the extraction-contract heuristic ("if `.history/` were deleted…"), the degraded-floor *explanation* (the disclosure rule itself is ESSENTIAL), the board-as-primary-surface *preference* sentence (the Submit write rule itself is ESSENTIAL).
